### 第三步半 · 御膳图鉴（看图点餐）——**默认上图**
```
mcp__mcd-mcp__query-meal-detail           # 对候选前 3 道取详情 → 取 data.image
python scripts/imperial_kitchen.py gallery --candidates <cands.json> --details <details.json> [--limit 3]
python scripts/imperial_kitchen.py meal-detail --raw <detail.json> [--show-modification]
```
- ⚠️ **已实跑确认：`query-meals` 菜单列表不返回图片字段**（到店、外送均无）。
  想让陛下看见菜，必须**逐道调用 `query-meal-detail`** 取 `data.image`（官方 CDN：menu-img.mcd.cn）。
- **默认策略：候选收敛后，主动对前 3 道调 `query-meal-detail` 上图**，不等陛下开口。
  陛下说"别上图"→ 停止配图，改纯文字；说"都看看"→ 可扩到 5 道，再多须陛下明示。
  节流的对象是**接口调用次数**而非图片张数（一张图在输出里只是一行 Markdown，约 20 token；
  一次套餐详情返回约 1300 token）——每多上图一道 = 多一次真实调用。
- **取详情是一箭双雕**：同一次 `query-meal-detail` 既取回图片，也取回套餐 `rounds`
  与必选口味组——正是第七步 `order-checklist` 的数据源。默认上图不增加任何额外调用。
- 图片一律**原样引用官方 CDN 地址**，臣不加工、不代存、不以他品之图充数；
  未取到图的餐品如实写明「官方未返回图片」，绝不编造链接。
- 官方展示规则：详情返回 `supportModify=true` 时名称后加【可特调】；
  **特调项默认不主动展开**，仅统计组数，陛下回复「查看特调」后再逐项呈上（加 `--show-modification`）。
- 套餐详情的 `rounds` 会给出各轮默认搭配（`isDefault=1`）与差价，可一并呈报。

#### 套餐选配与口味：浏览时不展开，**下单前必须逐条问**

官方展示规则说"不要主动展开特调选项"——那是**浏览时**不要刷屏。
一到下单环节，默认值落单就改不回来了，所以必须问清楚：

```
python scripts/imperial_kitchen.py order-checklist --details <details.json>
```

- **套餐**：有几轮选配就问几轮，把每轮的选中项原样写进订单复述。
  ⚠️ 绝不能只写「汉堡包」三个字——那等于把小食和饮品交给官方默认。
- **必选口味**（官方 `minValues>=1` 的特调组）：**必须问**。
  例如可口可乐（中杯）官方只有冰量四项：标准／去冰／多冰／少冰，默认"标准"，
  **不问就默认加冰**。臣不得拿官方默认当圣旨。
- **可选项**（`minValues=0`）：不必主动问，陛下提了再改。
- ⚠️ **"无糖"不是选项，是换一道膳品**（2026-10-22 实跑查证）：
  这杯可乐的官方数据里**没有无糖选项**；「无糖可口可乐」是另一个独立商品（编码 `903071`，11 元）。
  陛下若要无糖，臣应说明这是**换商品**，并去查该商品的详情与价格，不得假装能改选项。
